## How this repo is built: two investigations, one verdict

Most churn analyses run one lens. This one runs two in parallel, scores them
on effect size, ease of action, org fit, and feedback speed — then commits to
which finding to escalate. That choice is the deliverable
([synthesis](findings/05_synthesis.md)).

## Structure

```text
sql/        02_foundation.sql       MRR + monthly churn (Q0 audit … Q5 reconciliation)
            03a_cohort_retention.sql  per-(cohort, offset) retention table + validation
notebooks/  03a_cohort_retention.ipynb  pivot + heatmap (executed, asserts inline)
            04b_predictors.ipynb        onboarding features + churned-vs-retained (executed)
figures/    cohort_heatmap.png · predictor_comparison.png  (regenerated by the notebooks)
findings/   00_executive_summary.md · 02_foundation.md · 03a_cohort_retention.md
            04b_predictors.md · 05_synthesis.md · data_dictionary.md
docs/       schema.sql  (reference DDL reconstructed from information_schema)
```

- **M2 — Foundation** ([sql](sql/02_foundation.sql) · [brief](findings/02_foundation.md)): active/churned definitions, MRR by tier, 12-month trend. Everything downstream reuses these definitions.
- **M3 — Investigation A: cohort retention** ([sql](sql/03a_cohort_retention.sql) · [notebook](notebooks/03a_cohort_retention.ipynb) · [brief](findings/03a_cohort_retention.md)): activation-cohort heatmap above. Finding: retention is decided in month one; the 2026 uptick is broad-based.
- **M4 — Investigation B: behavioural predictors** ([notebook](notebooks/04b_predictors.ipynb) · [chart](figures/predictor_comparison.png) · [brief](findings/04b_predictors.md)): churned-vs-retained onboarding comparison. Finding: evaluation without collaboration predicts 36% churn.
- **M5 — Synthesis** ([brief](findings/05_synthesis.md)): M4 escalated first (CS watchlist now), M3 funded as the longer bet.

## Reproduce

Read-only Postgres (Neon). One env var, no other setup:

```bash
pip install -r requirements.txt
export SAAS_DSN='<read-only DSN>'   # never committed; notebooks read it from the environment
# SQL: run sql/*.sql in SQLTools (SET search_path TO saas; is included)
# Notebooks: run top-to-bottom; figures regenerate into figures/
```

`docs/schema.sql` + `findings/data_dictionary.md` describe the data (grain,
counts, and the quirks that shaped the definitions) so the analysis reads
without database access. Notebooks assert their own quality gates
(month-0 = 100%, no cell > 100%) and were last executed end-to-end in this
environment — see stored outputs.
